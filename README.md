# Customer Deduplication System

نظام يمنع تسجيل العملاء المكررين: بيقرا ملف CSV، بيفحص كل عميل على 3 بوابات، وبيحفظه في قاعدة بيانات سحابية (Neon PostgreSQL).

🌐 **نموذج التسجيل:** https://customer-dedup-system-qp9xa.faable.link

## المشكلة
نفس العميل بيتسجل أكتر من مرة بحروف كبيرة أو مسافات زيادة أو اسم متقارب، فالداتا بتتلخبط والتقارير بتبقى غلط.

## إزاي بيشتغل
أول حاجة تنضيف: lowercase وإزالة المسافات الزيادة، وبعدين:

| البوابة | الفحص | النتيجة |
|---|---|---|
| 1. الصيغة | Regex للإيميل والموبايل (11 رقم مصري) والاسم مش فاضي | غلط ← `rejected_records` (invalid) |
| 2. التطابق | SHA-256 Hash للصف كله | نفس البيانات ← `rejected_records` (duplicate) |
| 3. التشابه | Fuzzy Matching (rapidfuzz) على الاسم، بس مع الصفوف اللي نفس الإيميل أو الموبايل | أكتر من 95% ← مكرر، من 80 لـ 95% ← `review_queue`، نفس الموبايل أو الإيميل باسم مختلف ← `review_queue` |

غير كده العميل بيتحفظ في `customers`. وفيه `UNIQUE` على الإيميل وعلى الـ Hash كحماية أخيرة، وكل مرفوض بيتسجل مع السبب.

## النتائج
على `customers.csv` (130 صف فيها تكرار وأخطاء متعمدة):

| الإجمالي | اتضاف | مكرر | غلط (Invalid) | للمراجعة |
|---|---|---|---|---|
| 130 | 101 | 20 | 6 | 3 |

**الأداء:** Index على عمود الموبايل نزّل وقت الاستعلام على السيرفر من **0.101 ms إلى 0.039 ms** (حوالي 2.6 مرة أسرع) على 1000 صف.

## ملفات المشروع
- `main.py`: الحارس، بيقرا الـ CSV ويعدّي الصفوف على البوابات ويطبع التقرير
- `find_duplicates.py`: بيدوّر على التكرار القديم في `customers` (`GROUP BY ... HAVING COUNT(*) > 1`) وبينقله للأرشيف بـ `--apply`
- `benchmark.py`: بيقيس الزمن قبل وبعد الـ Index
- `generate_data.py`: بيولّد داتا اختبار
- `app.py`: نموذج تسجيل العميل (Flask) على Faable

## التشغيل محلياً
```bash
pip install psycopg2-binary rapidfuzz
```
حطي رابط Neon في ملف `db_url.txt` (مش مرفوع على جيت هاب) أو في متغير `DATABASE_URL`، وبعدين:
```bash
python main.py
```
